# velog-mcp 기획서

- 작성: 2026-07-30
- 상태: 초안 (v0.1 구현과 함께 갱신)

## 1. 배경

Velog 에 글을 쓰는 일이 늘었는데, 초안 작성이 항상 **에디터 창에서 시작**한다.
자료는 터미널·레포·이슈 트래커에 있고 글은 브라우저에 있으니 왕복이 생긴다.

MCP 로 벨로그를 붙이면 이 왕복이 사라진다. 다만 붙이는 순간 **AI 가 내 블로그에
쓰기 권한을 갖는다**. 그래서 이 프로젝트의 설계 질문은 "무엇을 할 수 있게 할까"
가 아니라 **"무엇을 못 하게 못 박을까"** 였다.

## 2. 문제 정의

기존 구현 두 개를 조사한 결과 (2026-07-30 기준):

| | `velog-mcp` (stoneHee99) | `velog-mcp-claude` (seongwon030) |
| --- | --- | --- |
| ⭐ | 7 | 6 |
| 주간 다운로드 | 32 | 46 |
| 마지막 갱신 | 2026-04-24 | 2026-04-28 |
| 발행 | `write_post` 한 번에 **즉시 게시** | `publishPost` 별도 (양호) |
| 삭제 | `delete_post` 노출 | `deletePost` 노출 |
| 인증 | **macOS 키체인에서 Chrome 암호키 추출** 후 쿠키 DB 복호화 | 토큰 붙여넣기 |
| npm ↔ 소스 | 일치 | **npm 0.10.0 vs 소스 0.20.0** (10버전 뒤처짐) |

정리하면 세 가지가 걸렸다.

1. **되돌릴 수 없는 동작이 노출돼 있다.** 발행과 삭제가 도구 목록에 있으면,
   모델이 판단을 한 번 잘못하는 것만으로 공개 게시나 글 소실이 일어난다.
2. **인증이 과하다.** `security find-generic-password -s "Chrome Safe Storage"` 로
   Chrome 마스터 키를 가져오는 코드가 상주한다. 현재 SQL 은 `.velog.io` 의 토큰
   2개로 정확히 한정돼 있어 결백하지만, 그 키를 쥔 코드가 항상 돌 이유는 없다.
3. **공급망이 얇다.** 개인 1인 유지보수 + 주간 40회 내외 다운로드 + 3개월 정지.
   `npx -y` 로 최신을 끌어오는 설정이면 업데이트 한 번에 코드가 바뀐다.

## 3. 목표

**G1. 되돌릴 수 없는 동작을 코드에서 없앤다.**
정책이나 프롬프트가 아니라 **구현 부재**로 보장한다. 발행 mutation 을 호출하는
코드가 레포에 존재하지 않으면 모델이 아무리 원해도 발행할 수 없다.

**G2. 읽기는 아끼지 않는다.**
조회·검색·통계는 실수해도 되돌릴 게 없다. 여기서는 기능을 넓게 가져간다.

**G3. 토큰을 최소로 다룬다.**
환경변수로만 받고, 디스크에 쓰지 않고, 브라우저·키체인을 건드리지 않고,
로그·에러 메시지에 실리지 않게 한다.

**G4. 스키마 근거를 남긴다.**
벨로그 GraphQL 은 비공식이라 언제든 바뀐다. introspection 실측 결과를
`docs/api-reference.md` 에 날짜와 함께 박아두고, 깨졌을 때 diff 로 찾게 한다.

## 4. 비목표 (하지 않는 것)

- **발행**: `is_temp: false` 로 글을 공개하는 기능. 사람이 벨로그에서 누른다.
- **삭제**: 글·시리즈·댓글 삭제. 실수의 대가가 비대칭적으로 크다.
- **소셜 행위**: 좋아요·팔로우·댓글 작성. 남의 타임라인에 내 이름으로 흔적을
  남기는 일은 자동화 대상이 아니다.
- **계정 조작**: `unregister`(탈퇴)·프로필/이메일 변경. introspection 에 보이지만
  구현하지 않는다.
- **다중 계정**: 계정 하나만 다룬다.
- **오프라인 캐시·동기화**: 벨로그가 원본(single source of truth)이다.

## 5. 사용자 시나리오

**S1. 자료에서 초안으로**
> "이번 prom-client 기여 건으로 글 초안 잡아줘"
→ 대화 맥락으로 마크다운을 만들고 `velog_create_draft` 로 임시저장.
사용자는 벨로그에서 열어 고치고 직접 발행한다.

**S2. 내 글 되짚기**
> "작년에 쓴 HTTP/2 글 어디였지"
→ `velog_search_posts(username=…)` 로 찾아 본문까지 읽어온다.

**S3. 블로그 현황 파악**
> "내 글 중에 조회수 높은 순으로"
→ `velog_blog_stats` 가 `likes`·`views` 를 집계해 표로 준다.

**S4. 백업**
> "내 글 전부 마크다운으로 내려받아"
→ `velog_export_posts` 가 로컬 디렉터리에 파일로 쓴다.

**S5. 초안 이어쓰기**
> "어제 잡아둔 초안 이어서 마무리하자"
→ `velog_list_drafts` → `velog_update_draft`.

## 6. 성공 기준

| # | 기준 | 검증 방법 |
| --- | --- | --- |
| A1 | 발행 mutation 호출 코드가 **0곳** | `grep -r "is_temp.*false"` 결과 없음 + 테스트로 고정 |
| A2 | 삭제·소셜·계정 mutation 미구현 | 도구 목록 스냅샷 테스트 |
| A3 | 토큰이 디스크·로그에 안 남음 | 파일 쓰기 없음 검증 + 에러 마스킹 테스트 |
| A4 | 토큰 없이도 공개 조회 동작 | 무인증 통합 테스트 |
| A5 | 런타임 의존성 ≤ 2 | `package.json` 검사 |
| A6 | 스키마 변경 감지 | introspection diff 스크립트 |

## 7. 범위 (v0.1)

### 읽기 — 인증 불필요
`velog_get_post` · `velog_list_posts` · `velog_search_posts` ·
`velog_trending_posts` · `velog_recent_posts` · `velog_get_user` ·
`velog_list_series` · `velog_get_series` · `velog_get_tag` ·
`velog_user_tags` · `velog_trending_writers`

### 읽기 — 인증 필요
`velog_current_user` · `velog_list_drafts` · `velog_reading_list` ·
`velog_feed` · `velog_notifications`

### 쓰기 — 초안 한정
`velog_create_draft` · `velog_update_draft`

### 파생 기능 (API 단순 중계가 아닌 것)
`velog_blog_stats` — 내 글의 `views`/`likes`/`comments_count` 집계
`velog_export_posts` — 글을 프론트매터 붙인 마크다운 파일로 저장

## 8. 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 비공식 API 라 예고 없이 깨짐 | 스키마 실측을 문서로 고정 + diff 스크립트. 깨지면 어디가 바뀌었는지 즉시 나옴 |
| `access_token` 1시간 만료 | 만료를 **에러로 명확히** 알린다. 자동 갱신은 refresh 토큰을 상시 쓰게 하므로 v0.1 범위 밖 |
| 대량 호출로 이용약관 8조(정상 운영 방해) 저촉 | 페이지네이션 상한 + `export` 는 순차 호출 |
| 모델이 초안을 남발 | 초안은 벨로그에서 일괄 삭제 가능. 되돌릴 수 있는 실수만 허용한다는 설계 그대로 |

## 9. 법적 검토 (2026-07-30 확인)

- **이용약관** ([velog.io/policy/terms](https://velog.io/policy/terms)):
  자동화·크롤링·스크래핑·역설계에 대한 **명시 금지 조항 없음**. 제8조(이용제한)는
  "정상적인 서비스 운영 방해"와 "권한을 넘어선 접근"을 다룬다. 본인 계정 토큰으로
  본인 글을 다루는 것은 권한 내 행위.
- **게시물 저작권** (제5조 1항): 회원에게 귀속. 내 글은 내 것.
- **API 재구현**: `v3.velog.io/graphql` 스키마는 벨로그 소유이며, 본 구현은
  벨로그의 **introspection 응답에서 직접** 도출했다. 기존 두 패키지의 소스를
  옮겨오지 않았다. 인터페이스 재구현이 저작권 침해가 아니라는 점은
  Google v. Oracle (2021) 로 확립.

## 10. 열린 질문

- npm 배포 여부. 패키지명 `velog-mcp` 는 선점돼 있어 스코프명
  `@milcho0604/velog-mcp` 를 잡아둠. 공개 배포는 v0.1 안정화 후 판단.
- `refresh_token` 자동 갱신을 넣을 것인가. 편의 ↔ 상시 보관 위험의 교환.
- 이미지 업로드(`uploadImage`) 지원 여부. 초안에 이미지가 필요하면 결국 든다.
