# ADR 0006 — Claude Code 플러그인으로 배포한다

- 날짜: 2026-07-31
- 상태: 채택

## 맥락

ADR 0003 에서 토큰을 **환경변수로만** 받기로 했다. 디스크에 안 쓰고, 키체인도 안 본다.
그 결정은 지금도 유효하다 — 서버는 여전히 토큰을 파일로 쓰지 않는다.

문제는 **그 환경변수를 누가 어디에 적어두느냐**였다. 실제로는 이렇게 됐다:

```
~/.claude.json  →  mcpServers.velog.env.VELOG_REFRESH_TOKEN  = <30일짜리 계정 전권 토큰, 평문>
```

파일 권한이 `-rw-------` 이고 git 저장소 밖이라 당장 새는 건 아니다. 그래도
30일짜리 계정 전권 자격증명이 홈 디렉터리 JSON 에 평문으로 있는 상태다.

Claude Code 플러그인에는 `userConfig` 가 있고, `sensitive: true` 로 선언한 값은
**macOS 키체인**에 저장된다(키체인이 없는 플랫폼은 `~/.claude/.credentials.json`).
그 값은 `${user_config.KEY}` 로 `.mcp.json` 에 치환돼 서버에 env 로 들어온다.
서버 입장에서는 여전히 환경변수 하나다 — ADR 0003 을 바꾸지 않고 저장 위치만 옮긴다.

## 결정

저장소 하나가 마켓플레이스이자 플러그인 배포처가 된다.

```
velog-mcp/
├── .claude-plugin/marketplace.json     ← 마켓플레이스 `milcho`
└── plugins/velog/                      ← 플러그인 `velog`
    ├── .claude-plugin/plugin.json      ← userConfig 4개
    ├── .mcp.json                       ← npx 로 npm 패키지 실행
    └── README.md
```

이름은 공식 디렉터리의 서드파티 15개 관례를 따랐다 — `asana` · `github` · `linear`
처럼 **서비스 맨이름**이다. `velog-mcp` 같은 이름은 사용자가 설치하는 것이
'MCP' 가 아니라 '플러그인'이라 군더더기다.

## 실측이 내 전제를 뒤집었다

설계할 때 이렇게 봤다 — **"치환이 실패하면 `${user_config.x}` 가 글자 그대로 남는다."**
근거는 Claude Code 2.1.220 실행 파일 안의 이 검사였다:

```js
p = l.includes("${user_config.") ? "user_config_missing" : "url_invalid"
```

리터럴이 살아남는다는 전제 위에서만 성립하는 검사다. 그래서 그걸 막는 코드를 먼저 썼다.

그리고 **탐침 플러그인을 만들어 실제로 쟀다.** userConfig 를 아무것도 안 채우고
`claude --plugin-dir` 로 띄운 뒤, MCP 서버가 받는 env 를 그대로 파일에 적게 했다.

| `.mcp.json` 의 env 값 | 서버가 실제로 받는 것 |
| --- | --- |
| `${user_config.문자열}` (값 없음) | `""` — 키는 존재한다 |
| `${user_config.불린}` (`default: false`) | `"false"` |
| `${user_config.불린}` (default 없음, 값 없음) | `""` |
| `prefix-${user_config.x}-suffix` | `prefix--suffix` |
| **선언하지 않은 키를 참조** | **서버가 기동하지 않는다** |

전제가 틀렸다. 위의 `includes` 검사는 **URL 형태 서버 경로에만** 있고,
stdio 서버의 env 는 빈 문자열로 치환된다.

마지막 줄이 제일 아프다. `.mcp.json` 이 `plugin.json` 에 없는 키를 참조하면
Claude Code 가 그 MCP 서버를 **아무 말 없이 안 띄운다**. 대조군으로 확인했다 —
같은 매니페스트에서 참조를 선언된 키로만 바꾸자 서버가 정상 기동했다.
증상은 "플러그인은 깔렸는데 도구가 하나도 없음"이다. 오타 하나로 그렇게 된다.

## 그래서 코드가 하는 일이 바뀌었다

`src/plugin-env.ts` 는 이제 **"빈 값을 없음으로 굳히는 것"**이 본업이다.

지금도 소비 지점 셋은 빈 문자열을 알아서 걸러낸다 — `auth.ts` 의 `|| undefined`,
`chrome.ts` 의 `if (override)`, `capabilities.ts` 의 TRUTHY 집합. 셋 다 맞다.
그런데 **셋 다 따로** 맞는다. 그중 하나만 나중에 `?? undefined` 로 바뀌어도
빈 문자열이 토큰 행세를 하고, 그때 증상은 "토큰이 만료됐나?" 로 나타난다.
한 곳에서 지워 두면 그 회귀가 성립하지 않는다.

자리표시자 검사는 남겼다. 관찰한 건 **버전 하나의 동작**이지 보장된 계약이 아니고,
URL 서버 경로에는 그 사고가 실재한다. 비용은 정규식 하나다. 다만 주석에
"관찰된 적 없음"이라고 못 박아 뒀다 — 근거 없는 방어가 근거 있는 척하면 안 된다.

## 시끄럽지 않기로 한 것

플러그인은 설정 네 개를 **항상** 넘긴다. 토큰만 넣은 사용자에게 나머지 셋이
빈 값으로 온다. 그걸 매번 경고하면 경고를 읽지 않게 된다.

그래서 기동 로그가 말하는 건 두 경우뿐이다:

- **토큰이 비어서 왔다** → 읽기 전용이 된 이유를 짚는다. 나머지 빈 값은 언급하지 않는다.
- **자리표시자가 살아 왔다** → 관찰된 적 없는 일이다. 크게 알린다.

그리고 크롬 가용 여부는 **매번** 말한다. 그림 도구 3종은 크롬이 없으면 안 되는데,
그걸 처음 알게 되는 시점이 대개 "글 쓰다가 그림이 필요해진 순간"이다.
설치 직후에 알면 그때 해결할 수 있다.

## 배포 게이트 — `version` 이 핵심이다

`plugin.json` 에 `version` 을 **반드시** 적는다. 안 적으면 커밋 SHA 가 버전이 되어
**푸시하는 족족 사용자에게 흘러간다.** 적어두면 그 값을 올릴 때만 나간다.

PR 로 작업하는 것과는 다른 축이다. PR 은 master 를 깨끗하게 유지하고,
`version` 은 사용자에게 나가는 순간을 정한다. 둘 다 필요하다.

버전이 네 곳에 있다 — `package.json` · `plugin.json` · `.mcp.json` 의 npx 핀 ·
`SERVER_VERSION`. 손으로 맞추지 않는다. 테스트 P8 이 넷을 대조한다.

## 안 고른 것

**`.mcp.json` 에 `dist/` 를 동봉하고 `node ${CLAUDE_PLUGIN_ROOT}/dist/index.js` 로 실행**
— `dist/` 를 git 에 넣어야 한다. 소스 한 줄 고칠 때마다 빌드 산출물 커밋이 따라붙어
저장소가 지저분해진다.

**marketplace 의 `npm` 소스 타입** — 플러그인 자체가 npm 패키지가 되어 오프라인에도
강하고 아티팩트가 하나로 준다. 매력적인데, 그때 **런타임 의존성 두 개
(`@modelcontextprotocol/sdk`, `zod`)가 설치되는지 확인하지 못했다.** 문서에 명시가
없다. 확인되면 옮길 만하다.

지금은 **`npx -y @milcho0604/velog-mcp@<정확한 버전>`** 이다. 의존성 설치가 확실하고,
정확한 버전을 핀하므로 `npx` 가 캐시에서 해결한다. 오프라인 첫 설치는 안 된다 —
이건 문서에 적어 사용자가 알게 한다.

`velog-mcp` 라는 이름은 npm 에 이미 있다(`stoneHee99`, 0.2.2). 그래서 스코프
패키지 `@milcho0604/velog-mcp` 를 쓴다.

## 코덱스가 뒤집은 것 — `npx` 는 토큰 경계를 넓힌다

교차검증에서 이 지적이 나왔고, 재보니 맞았다.

`.mcp.json` 의 `env` 는 최종 서버에만 가는 게 아니다. **먼저 실행되는 `npx`/`npm`
프로세스에도 그대로 들어간다.** 그러니 "A6 가 토큰이 velog.io 밖으로 못 나가게
강제한다"는 설명은 **이 실행 방식 전체에 대해서는 성립하지 않는다.** A6 는 이
저장소의 코드만 본다.

세 가지를 했다:

1. **문구를 정확히 고쳤다.** 매니페스트 설명과 README 에서 "어디로도 안 나간다"를
   "이 서버가 싣는 목적지는 velog.io 뿐"으로 좁히고, npx 경계를 명시했다.
2. **실측했다.** 운영 의존성 트리에 `install`·`postinstall` 스크립트가 하나도 없다.
   (`prepare` 는 여럿 있지만 게시된 tarball 설치에서는 돌지 않는다.)
3. **막았다.** `.mcp.json` 에 `npm_config_ignore_scripts=true` 를 넣었다.
   이 환경변수가 실제로 `ignore-scripts` 를 켜는 것은 실행해서 확인했다.
   전이 의존성이 나중에 스크립트를 추가해도 돌지 않는다. (테스트 P17)

완전히 없애려면 npm 을 실행 경로에서 빼야 한다 — 의존성 번들이 필요하고,
그건 런타임 의존성 2개를 유지하는 이 저장소의 방식과 맞바꿔야 한다. 지금은 안 했다.

## 코덱스가 뒤집은 것 — `access(X_OK)` 는 디렉터리도 통과한다

크롬 경로 설정이 `file` 타입이라 macOS 파일 선택기가 `.app` **번들 자체**를 돌려줄 수
있다. 번들은 디렉터리이고, POSIX 에서 디렉터리의 `X_OK` 는 '실행 가능'이 아니라
'탐색 가능'이다. 실측:

```
X_OK 통과 | isFile=false | /Applications/Google Chrome.app
X_OK 통과 | isFile=true  | /Applications/Google Chrome.app/Contents/MacOS/Google Chrome
```

증상이 고약하다 — 기동 로그는 "그림 도구 사용 가능"이라고 말해놓고, 정작 그리려
할 때 `spawn` 이 실패한다. **말과 실제가 어긋나는 종류의 버그**다.

`stat().isFile()` 을 함께 본다. 그리고 번들을 골랐으면 안쪽 실행 파일로 바꿔준다 —
번들을 고르는 건 사용자 실수가 아니라 파일 선택기의 자연스러운 결과다.

## 테스트가 약했던 것 — 코덱스의 반례 둘

**게이트 두 개를 서로 바꿔도 통과했다.** `allow_public` ↔ `allow_profile` 을 맞바꾸면
키 집합은 그대로다. 그런데 사용자는 프로필 수정만 켰는데 공개 발행이 열린다.
토큰과 크롬 경로를 바꿔도 통과했고, 그 경우 토큰이 크롬 오류 메시지에 실려
stderr 로 나갈 수 있다. → **매핑 전체를 그대로 못 박았다**(P6). 명령·인자도(P16).

**`server.connect()` 를 통째로 지워도 통과했다.** 기동 로그가 먼저 나오기 때문이다.
즉 "말은 하는데 서버가 아닌" 상태를 못 잡았다. → **실제 JSON-RPC `initialize` 와
`tools/list` 를 던져 응답을 받는다**(P18). 서버 이름·버전·도구 수까지 확인한다.

## 3차에서 나온 것 — 정확한 버전을 핀해도 의존성은 안 고정된다

`.mcp.json` 이 `@milcho0604/velog-mcp@0.4.0` 을 정확히 핀한다. 그런데 **그 안의
의존성은 `^1.30.0`·`^4.4.3` 캐럿 범위**다. 나중에 콜드 설치하면 같은 0.4.0 이어도
더 새 의존성을 받고, 그 코드는 **토큰이 든 같은 프로세스에서** 돈다.
`npm_config_ignore_scripts` 는 설치 스크립트만 막지 런타임 코드는 못 막는다.

`npm-shrinkwrap.json` 을 쓴다. `package-lock.json` 과 달리 **발행물에 실려**
트리 전체를 고정한다(운영 93개). 대가는 명확하다 — 의존성 보안 패치가 자동으로
안 온다. 릴리스를 우리가 쥐는 대신 갱신 책임도 우리가 진다. 30일짜리 계정 전권
자격증명을 들고 도는 CLI 라서 이쪽을 택했다.

⚠️ 함정 하나: `files` 화이트리스트가 있으면 shrinkwrap 도 **안 실린다**(실측).
`files` 에 명시해야 한다. 넣기 전/후로 tarball 을 실제로 풀어 확인했다(96→97개).

## 3차에서 나온 것 — `dist/` 는 어떤 검사도 안 받고 있었다

테스트는 `src/index.ts` 를 띄운다. 사용자가 실행하는 건 `dist/index.js` 다.
그런데 `dist/` 는 `.gitignore` 대상이라 lint 도 테스트도 닿지 않는다.
즉 **dist 에서만 깨진 상태는 테스트가 전부 통과해도 안 잡힌다.**

`prepublishOnly` 에 관문을 걸었다 — `npm publish` 가 반드시 거치고 사람이 건너뛸 수
없다. 실제 `dist/index.js` 를 띄워 MCP 핸드셰이크를 하고, 버전이 `package.json` 과
같은지(낡은 산출물 탐지), 도구가 다 뜨는지, **stdout 에 프로토콜 아닌 줄이 없는지**
본다. 마지막 것도 3차 지적이다 — 원래 파싱 실패한 줄을 조용히 버려서,
기동 경로에 `console.log` 를 넣어도 통과했다.

관문이 실제로 막는지 두 가지로 확인했다: dist 버전을 0.3.0 으로 바꾸면 "빌드
산출물이 낡았습니다", `console.log` 를 넣으면 "stdout 에 프로토콜 아닌 줄" 로 중단된다.

## 3차에서 나온 것 — "그림 도구 3종"이 틀렸다

`velog_upload_image` 는 로컬 파일을 읽어 올릴 뿐 크롬을 안 쓴다. 크롬이 필요한 건
`velog_render_diagram` 과 `velog_render_cover` **둘**이고 나머지 19개는 없어도 된다.
크롬 없는 사용자가 멀쩡히 되는 업로드까지 못 쓴다고 오해할 안내였다.

**개수를 세지 않고 이름을 적는다.** 숫자는 코드와 따로 놀지만 이름은 테스트가
실물(`tools/list`)과 대조할 수 있다. 렌더 호출 지점 수도 함께 세서, 세 번째 도구가
렌더를 쓰기 시작하면 목록이 낡았다고 실패한다.

## 테스트가 자기 자신을 잡은 이야기

개인정보 차단(P21)을 **git 추적 파일 전체**로 넓혔더니 두 번 걸렸다.

1. 코덱스가 든 예시 주소를 주석에 적었는데 그게 잡혔다.
2. 규칙 자체를 시험하려고 나쁜 주소·경로를 fixture 로 넣었더니 그것도 잡혔다.

두 번째는 진짜 딜레마다 — 스캔에서 이 파일을 빼면 구멍이 되고, 두면 fixture 가 걸린다.
**실행할 때 조립하는 것**으로 풀었다(`String.fromCodePoint(0x40)`, 배열 `join('/')`).
소스에는 온전한 주소도 홈 경로도 없고, 규칙은 여전히 시험된다.

그리고 규칙을 시험하는 사례가 왜 필요한지도 변이 검증이 알려줬다 — 예외를
'문자열에 noreply 가 들어 있으면 통과'로 되돌려도, **지금 그 허점을 찌르는 값이
파일에 없어서** 테스트가 통과했다. 실제 파일만 훑는 검사는 규칙의 느슨함을 못 본다.

## 결과

- 토큰이 `~/.claude.json` 평문에서 macOS 키체인으로 간다

## 남은 것

공식 디렉터리(`claude-plugins-official`)는 **신청 절차가 없다** — Anthropic 재량이다.
서드파티가 갈 수 있는 곳은 `claude-plugins-community` 이고 Console 폼으로 제출한다.
거기 올리면 승인 후 CI 가 커밋을 따라 핀을 올리므로, `version` 게이트가 더 중요해진다.
제출 전에 정해야 할 것은 하나 — **모르는 사람에게 "브라우저 쿠키에서 토큰을 꺼내라"고
시키는 것을 어떻게 다룰지**다. 고칠 수 없고(벨로그에 API 가 없다) 드러내는 수밖에 없다.
