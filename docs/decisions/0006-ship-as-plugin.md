# ADR 0006 — Claude Code 플러그인으로 배포한다

- 날짜: 2026-07-31
- 상태: 채택

## 맥락

ADR 0003 에서 토큰을 **환경변수로만** 받기로 했다. 디스크에 안 쓰고, 키체인도 안 본다.
그 결정은 지금도 유효하다 — 서버는 여전히 토큰을 파일로 쓰지 않는다.

문제는 **그 환경변수를 누가 어디에 적어두느냐**였다. 실제로는 이렇게 됐다:

```
~/.claude.json  →  mcpServers.velog.env.VELOG_REFRESH_TOKEN  = <30일짜리 계정 전권 토큰, 평문>
```

파일 권한이 `-rw-------` 이고 git 저장소 밖이라 당장 새는 건 아니다. 그래도
30일짜리 계정 전권 자격증명이 홈 디렉터리 JSON 에 평문으로 있는 상태다.

Claude Code 플러그인에는 `userConfig` 가 있고, `sensitive: true` 로 선언한 값은
**macOS 키체인**에 저장된다(키체인이 없는 플랫폼은 `~/.claude/.credentials.json`).
그 값은 `${user_config.KEY}` 로 `.mcp.json` 에 치환돼 서버에 env 로 들어온다.
서버 입장에서는 여전히 환경변수 하나다 — ADR 0003 을 바꾸지 않고 저장 위치만 옮긴다.

## 결정

저장소 하나가 마켓플레이스이자 플러그인 배포처가 된다.

```
velog-mcp/
├── .claude-plugin/marketplace.json     ← 마켓플레이스 `milcho-plugins`
└── plugins/velog/                      ← 플러그인 `velog`
    ├── .claude-plugin/plugin.json      ← userConfig 4개
    ├── .mcp.json                       ← npx 로 npm 패키지 실행
    └── README.md
```

이름은 공식 디렉터리의 서드파티 15개 관례를 따랐다 — `asana` · `github` · `linear`
처럼 **서비스 맨이름**이다. `velog-mcp` 같은 이름은 사용자가 설치하는 것이
'MCP' 가 아니라 '플러그인'이라 군더더기다.

## 실측이 내 전제를 뒤집었다

설계할 때 이렇게 봤다 — **"치환이 실패하면 `${user_config.x}` 가 글자 그대로 남는다."**
근거는 Claude Code 2.1.220 실행 파일 안의 이 검사였다:

```js
p = l.includes("${user_config.") ? "user_config_missing" : "url_invalid"
```

리터럴이 살아남는다는 전제 위에서만 성립하는 검사다. 그래서 그걸 막는 코드를 먼저 썼다.

그리고 **탐침 플러그인을 만들어 실제로 쟀다.** userConfig 를 아무것도 안 채우고
`claude --plugin-dir` 로 띄운 뒤, MCP 서버가 받는 env 를 그대로 파일에 적게 했다.

| `.mcp.json` 의 env 값 | 서버가 실제로 받는 것 |
| --- | --- |
| `${user_config.문자열}` (값 없음) | `""` — 키는 존재한다 |
| `${user_config.불린}` (`default: false`) | `"false"` |
| `${user_config.불린}` (default 없음, 값 없음) | `""` |
| `prefix-${user_config.x}-suffix` | `prefix--suffix` |
| **선언하지 않은 키를 참조** | **서버가 기동하지 않는다** |

전제가 틀렸다. 위의 `includes` 검사는 **URL 형태 서버 경로에만** 있고,
stdio 서버의 env 는 빈 문자열로 치환된다.

마지막 줄이 제일 아프다. `.mcp.json` 이 `plugin.json` 에 없는 키를 참조하면
Claude Code 가 그 MCP 서버를 **아무 말 없이 안 띄운다**. 대조군으로 확인했다 —
같은 매니페스트에서 참조를 선언된 키로만 바꾸자 서버가 정상 기동했다.
증상은 "플러그인은 깔렸는데 도구가 하나도 없음"이다. 오타 하나로 그렇게 된다.

## 그래서 코드가 하는 일이 바뀌었다

`src/plugin-env.ts` 는 이제 **"빈 값을 없음으로 굳히는 것"**이 본업이다.

지금도 소비 지점 셋은 빈 문자열을 알아서 걸러낸다 — `auth.ts` 의 `|| undefined`,
`chrome.ts` 의 `if (override)`, `capabilities.ts` 의 TRUTHY 집합. 셋 다 맞다.
그런데 **셋 다 따로** 맞는다. 그중 하나만 나중에 `?? undefined` 로 바뀌어도
빈 문자열이 토큰 행세를 하고, 그때 증상은 "토큰이 만료됐나?" 로 나타난다.
한 곳에서 지워 두면 그 회귀가 성립하지 않는다.

자리표시자 검사는 남겼다. 관찰한 건 **버전 하나의 동작**이지 보장된 계약이 아니고,
URL 서버 경로에는 그 사고가 실재한다. 비용은 정규식 하나다. 다만 주석에
"관찰된 적 없음"이라고 못 박아 뒀다 — 근거 없는 방어가 근거 있는 척하면 안 된다.

## 시끄럽지 않기로 한 것

플러그인은 설정 네 개를 **항상** 넘긴다. 토큰만 넣은 사용자에게 나머지 셋이
빈 값으로 온다. 그걸 매번 경고하면 경고를 읽지 않게 된다.

그래서 기동 로그가 말하는 건 두 경우뿐이다:

- **토큰이 비어서 왔다** → 읽기 전용이 된 이유를 짚는다. 나머지 빈 값은 언급하지 않는다.
- **자리표시자가 살아 왔다** → 관찰된 적 없는 일이다. 크게 알린다.

그리고 크롬 가용 여부는 **매번** 말한다. 그림 도구 3종은 크롬이 없으면 안 되는데,
그걸 처음 알게 되는 시점이 대개 "글 쓰다가 그림이 필요해진 순간"이다.
설치 직후에 알면 그때 해결할 수 있다.

## 배포 게이트 — `version` 이 핵심이다

`plugin.json` 에 `version` 을 **반드시** 적는다. 안 적으면 커밋 SHA 가 버전이 되어
**푸시하는 족족 사용자에게 흘러간다.** 적어두면 그 값을 올릴 때만 나간다.

PR 로 작업하는 것과는 다른 축이다. PR 은 master 를 깨끗하게 유지하고,
`version` 은 사용자에게 나가는 순간을 정한다. 둘 다 필요하다.

버전이 네 곳에 있다 — `package.json` · `plugin.json` · `.mcp.json` 의 npx 핀 ·
`SERVER_VERSION`. 손으로 맞추지 않는다. 테스트 P8 이 넷을 대조한다.

## 안 고른 것

**`.mcp.json` 에 `dist/` 를 동봉하고 `node ${CLAUDE_PLUGIN_ROOT}/dist/index.js` 로 실행**
— `dist/` 를 git 에 넣어야 한다. 소스 한 줄 고칠 때마다 빌드 산출물 커밋이 따라붙어
저장소가 지저분해진다.

**marketplace 의 `npm` 소스 타입** — 플러그인 자체가 npm 패키지가 되어 오프라인에도
강하고 아티팩트가 하나로 준다. 매력적인데, 그때 **런타임 의존성 두 개
(`@modelcontextprotocol/sdk`, `zod`)가 설치되는지 확인하지 못했다.** 문서에 명시가
없다. 확인되면 옮길 만하다.

지금은 **`npx -y @milcho0604/velog-mcp@<정확한 버전>`** 이다. 의존성 설치가 확실하고,
정확한 버전을 핀하므로 `npx` 가 캐시에서 해결한다. 오프라인 첫 설치는 안 된다 —
이건 문서에 적어 사용자가 알게 한다.

`velog-mcp` 라는 이름은 npm 에 이미 있다(`stoneHee99`, 0.2.2). 그래서 스코프
패키지 `@milcho0604/velog-mcp` 를 쓴다.

## 결과

- 토큰이 `~/.claude.json` 평문에서 macOS 키체인으로 간다
- 설치가 두 줄이 된다
- 새 테스트 25개(P1~P14), 변이 검증 18/18
- `claude plugin validate --strict` 통과

## 남은 것

공식 디렉터리(`claude-plugins-official`)는 **신청 절차가 없다** — Anthropic 재량이다.
서드파티가 갈 수 있는 곳은 `claude-plugins-community` 이고 Console 폼으로 제출한다.
거기 올리면 승인 후 CI 가 커밋을 따라 핀을 올리므로, `version` 게이트가 더 중요해진다.
제출 전에 정해야 할 것은 하나 — **모르는 사람에게 "브라우저 쿠키에서 토큰을 꺼내라"고
시키는 것을 어떻게 다룰지**다. 고칠 수 없고(벨로그에 API 가 없다) 드러내는 수밖에 없다.
